# Лабораторная работа 2. Классы и инкапсуляция

## 1. Цель работы

Научиться создавать собственные классы в Java, проверять корректность данных при создании объектов и защищать состояние объектов с помощью инкапсуляции.

## 2. Описание класса ProjectTask

`ProjectTask` представляет задачу в программном проекте.

Класс хранит идентификатор задачи, её название, текущий статус и оценку трудоёмкости в часах. Он позволяет изменять статус задачи и увеличивать оценку трудоёмкости с помощью специальных методов.

## 3. Поля класса

| Поле | Тип | Назначение |
|---|---|---|
| `id` | `String` | Идентификатор задачи |
| `title` | `String` | Название задачи |
| `status` | `TaskStatus` | Текущий статус задачи |
| `estimatedHours` | `int` | Оценка трудоёмкости в часах |

Все поля имеют модификатор доступа `private`. Поля `id` и `title` дополнительно объявлены как `final`, поскольку их значения не должны изменяться после создания объекта.

## 4. Инварианты класса

Для любого корректно созданного объекта `ProjectTask` должны выполняться следующие условия:

1. Идентификатор `id` не равен `null` и не является пустой строкой.
2. Название `title` не равно `null` и не является пустой строкой.
3. Статус `status` не равен `null`.
4. Оценка трудоёмкости `estimatedHours` не может быть отрицательной.
5. Идентификатор и название задачи не изменяются после создания объекта.
6. Статус изменяется только через метод `changeStatus`.
7. Оценка трудоёмкости увеличивается только на положительное количество часов.

## 5. Допустимые статусы задачи

Для представления состояния задачи используется перечисление `TaskStatus`:

- `TODO` — задача ожидает выполнения;
- `IN_PROGRESS` — задача находится в процессе выполнения;
- `DONE` — задача завершена.

Использование `enum` ограничивает набор допустимых статусов заранее определёнными значениями.

## 6. Конструктор и проверка данных

Конструктор `ProjectTask` принимает идентификатор, название, статус и оценку трудоёмкости.

Перед присваиванием значений полям выполняются проверки входных данных. Если обязательное значение отсутствует или оценка трудоёмкости отрицательна, выбрасывается исключение `IllegalArgumentException`.

Таким образом, конструктор не позволяет создать объект с недопустимыми значениями полей.

## 7. Методы класса

| Метод | Назначение |
|---|---|
| `getId()` | Возвращает идентификатор задачи |
| `getTitle()` | Возвращает название задачи |
| `getStatus()` | Возвращает текущий статус |
| `getEstimatedHours()` | Возвращает оценку трудоёмкости |
| `changeStatus(TaskStatus status)` | Изменяет статус после проверки входного значения |
| `increaseEstimatedHours(int hours)` | Увеличивает оценку трудоёмкости на положительное число часов |

Для полей не создаются универсальные setter-методы. Изменение состояния выполняется через методы, которые проверяют допустимость операции.

## 8. Инкапсуляция

Инкапсуляция обеспечивает контролируемый доступ к состоянию объекта.

Закрытые поля `private` нельзя напрямую изменять из внешнего кода. Для чтения предусмотрены методы доступа, а для изменения статуса и оценки трудоёмкости — специальные методы с проверками.

Это позволяет поддерживать инварианты класса и предотвращать некорректное изменение состояния задачи.

## 9. Проверка работы

Корректность реализации проверяется с помощью автоматических тестов JUnit.

Тесты должны проверять:

- создание задачи с корректными значениями;
- отклонение `null` и пустых обязательных полей;
- отклонение отсутствующего статуса;
- отклонение отрицательной оценки трудоёмкости;
- корректное изменение статуса;
- увеличение оценки трудоёмкости на положительное число часов;
- отклонение недопустимого значения при увеличении оценки.

Для запуска тестов используется команда:

```bash
./mvnw -pl lab02 test
```

## 10. Вывод

В ходе лабораторной работы изучаются классы, конструкторы, перечисления, модификаторы доступа и инкапсуляция в Java. Реализация `ProjectTask` демонстрирует, как объединять данные и поведение в одном классе и обеспечивать корректность состояния объекта с помощью проверок и специализированных методов.
